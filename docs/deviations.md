# Deviations Register

| ID | Requirement / Claim | Deviation in Current Environment | Impact & Rationale | Remediation / Production Path |
|---|---|---|---|---|
| DEV-001 | Desktop Runtime Execution (Tauri 2 Rust binary + PyInstaller onedir exe) | The Arena workspace runs Linux x64 and has no local Rust/Cargo toolchain or Windows desktop session, so it cannot launch the installed Tauri app or perform the required real Windows shell-crash test. | CI run `43463729769` passed Windows and Ubuntu validation, locked Rust tests/builds, the frozen-sidecar handshake/EOF smoke, NSIS install, resource staging, and post-install IPC smoke. Windows CI runs non-integration Rust unit tests only; Linux runs the MockRuntime RPC loop tests. Installer `EnergyBaseline-Windows-NSIS-M1` (artifact `14057359462`) was uploaded. None of these tests forcibly terminates the actual desktop process; runtime acceptance is not claimed. | Complete `docs/manual_windows_runtime_check.md` on Windows 10/11 with this artifact, record that all tracked sidecar descendants exit within 5 seconds after force-terminating the verified app, and retain non-sensitive evidence. |
| DEV-002 | Python Scientific Stack (`numpy`, `scipy`, `statsmodels`, `arch`, `scikit-learn`, `torch`, `mapie`, `sqlglot`) | Container Python 3.10.12 has standard library only (`sqlite3`, `json`, `unittest`, etc.) without external pip wheels. | `sidecar/energybaseline/sql/guard.py` uses `sqlglot.parse` when installed and falls back to a verified lexical/structural AST validator. In-browser statistical and modeling engines execute pure deterministic TypeScript implementations. | Install pinned `requirements-lock.txt` in the Windows Python 3.11+ build environment. |
| DEV-003 | TanStack Table v9 Pinning | Installed `@tanstack/react-table` resolved to `9.3.1` (stable v9 API using `tableFeatures`, `createColumnHelper`, `useTable`, `table.FlexRender`) paired with `@tanstack/react-virtual` `3.14.26`. | Exact v9.3.1 exports were verified in `node_modules/@tanstack/react-table` prior to authoring `src/components/DataTable.tsx`. | Pin `9.3.1` in lockfile. |
| DEV-004 | Optuna `CmaEsSampler` & Bayesian Decision Framework (TCP-14) | Optuna CMA-ES and Bayesian ROPE inference are deferred in the in-browser engine; TPE-style / grid-search tuning and frequentist + equivalence (TOST) decision rules ship active. | Low impact for classical & tree baseline selection; clearly listed. | Enable `optuna` + `cmaes` in Python 3.11+ sidecar worker pool. |
| DEV-005 | Tauri shell capability/resource path (ARC-1..ARC-6) | The release launcher resolves `app.path().resource_dir()/energybaseline_sidecar/energybaseline_sidecar.exe` and calls `app.shell().command(...).spawn()` from Rust. That direct Rust API call does not use the shell plugin's webview IPC `shell:allow-spawn` scope. The unused permission was removed from `main.json`; no frontend code calls the shell plugin spawn API. | The former `$RESOURCE/energybaseline_sidecar/energybaseline_sidecar.exe` capability entry was not the active spawn boundary and must not be described as one. CI verifies resource staging and sidecar IPC, but does not launch the installed Tauri app. | During the required manual Windows check, launch the installed app and confirm Ready to verify the Rust-resolved resource path works in the packaged app, then run the crash/orphan procedure. If startup fails, record the resolved path and error; do not infer a capability mismatch or mark the check passed. |
| DEV-006 | Production analysis RPC / `analysis.run` and SQL execution | Analysis, modeling, statistics, and reporting still execute in frontend TypeScript. Python currently implements bootstrap health/status; `analysis.run` remains a stub that returns not-implemented, and `sql.run_query` validates read-only SQL but does not execute it. | Phase 1 is runtime plumbing only and does not move computation to the sidecar. Neither RPC should be described as “Partial” or as a working production path. | Keep Phase 2, Phase 3, and Phase 6 not started until their gates are met. Implement `analysis.run` before Phase 4 governance; Phase 3 waits for sidecar diagnostics RPC. Keep `sql.run_query` non-executing until its guard and execution path are approved and hardened. |
